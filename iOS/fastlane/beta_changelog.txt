0.4.4 (build 148) — fixes trash requests that got permanently stuck.

If a trash run failed partway through — server unreachable, connection dropped mid-run, VPN down — every later retry failed with "Immich returned HTTP 400: A tag with that name already exists", and the request sat in the queue for good. No amount of retrying could clear it.

The cause was on cairn's side. Every trash run writes a breadcrumb tag to Immich so the run can be reconstructed later, and cairn was creating those tags with an endpoint that rejects duplicates instead of the one that reuses an existing tag. Since a retry reuses its original run's tag, the second attempt was refused every time.

- Trash retries now reuse the run's existing tag rather than failing on it.
- Requests already stuck on this error are cleared when you update — they run on your next sync, no tap needed.
- Run breadcrumbs now nest under cairn / v1 / run in Immich's tag list instead of sitting there as one flat entry.

To test: after updating, open Status → Pending trashes. If you had a stuck request, it should drain on the next sync on its own — you shouldn't need "Retry all now". Confirm the photos actually reached Immich's Trash. To exercise the original failure path, drop your server or VPN mid-sync so a trash run fails, bring it back, and check that the queued request drains on the following sync instead of wedging.
